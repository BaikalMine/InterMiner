# InterMiner для Keryx (KRX): инструкция по запуску

После хардфорка H6 сеть принимает только блоки с PoM v3. Для майнинга Keryx нужна
версия **InterMiner 1.2.5 или новее**. Версии до 1.2.3 не поддерживают H6, а в 1.2.4
использовалась неверная точка активации H6, поэтому ее также необходимо обновить.

InterMiner 1.2.5 совместим с H7. Для майнера H7 не меняет команду запуска, алгоритм,
модели или сертификат direct-solo. Операторы пулов и solo-нод должны обновить Keryx
node до версии **1.4.8 или новее**.

Для PPLNS достаточно адреса кошелька. Для direct-solo дополнительно нужен сертификат,
который владелец адреса один раз выпускает в своем кошельке. Приватный ключ при этом
никуда не передается.

## 1. Требования

| Параметр | Требование |
| --- | --- |
| Видеокарта | NVIDIA с compute capability 7.0 или новее (RTX 20/30/40/50 и совместимые CMP) |
| Видеопамять | не менее 8 ГБ для минимального H6-профиля |
| Драйвер | актуальный драйвер NVIDIA с поддержкой видеокарты и CUDA 12 |
| Свободное место | около 10 ГБ |
| Версия майнера | **1.2.5 или новее** |

Текущий Keryx H6 не поддерживается на NVIDIA Pascal/GTX 10 и AMD/OpenCL. Для RTX 50
используйте свежий драйвер с поддержкой Blackwell.

Проверить драйвер в Windows или Linux:

```text
nvidia-smi
```

При первом запуске майнер скачивает актуальную языковую модель размером около 6,5 ГБ.
Это нормально и выполняется один раз.

## 2. PPLNS

Для обычного майнинга на PPLNS сертификат не нужен.

Linux:

```bash
LD_LIBRARY_PATH="$PWD:${LD_LIBRARY_PATH}" ./InterMiner-cuda \
  -a keryxhash \
  -s stratum+tcp://krx.baikalmine.com:9020 \
  -w keryx:ВАШ_АДРЕС.rig01 \
  --threads 0 --cuda-no-blocking-sync
```

Windows:

```bat
InterMiner-cuda.exe -a keryxhash -s stratum+tcp://krx.baikalmine.com:9020 -w keryx:ВАШ_АДРЕС.rig01 --threads 0 --cuda-no-blocking-sync
```

`rig01` — произвольное имя воркера. `--threads 0` отключает CPU-майнинг.

## 3. Direct-solo

В direct-solo награда блока назначается непосредственно вашему адресу. После H6 в
блоке должно быть доказательство, что локальный escrow-ключ майнера авторизован
владельцем этого адреса. Пул не может выпустить сертификат вместо владельца адреса.

Важно: используйте адрес кошелька, приватным ключом которого вы владеете. Адрес биржи,
кастодиального сервиса или другого кошелька без доступа к приватному ключу не подходит
для H6 direct-solo.

### Шаг 1. Получите escrow-ключ майнера

Запустите майнер без сертификата:

Linux:

```bash
LD_LIBRARY_PATH="$PWD:${LD_LIBRARY_PATH}" ./InterMiner-cuda \
  -a keryxhash \
  -s stratum+tcp://krx-solo.baikalmine.com:9021 \
  -w keryx:ВАШ_АДРЕС.rig01 \
  --threads 0 --cuda-no-blocking-sync
```

Windows:

```bat
InterMiner-cuda.exe -a keryxhash -s stratum+tcp://krx-solo.baikalmine.com:9021 -w keryx:ВАШ_АДРЕС.rig01 --threads 0 --cuda-no-blocking-sync
```

Используйте именно имя `krx-solo.baikalmine.com`: по нему майнер определяет режим
direct-solo. При первом запуске майнер создаст `escrow.key`, остановится и напечатает:

```text
H6 escrow key to authorize in the payout wallet: <64 hex>
```

Скопируйте 64 шестнадцатеричных символа после двоеточия.

### Шаг 2. Авторизуйте ключ

Откройте кошелек Keryx, которому принадлежит указанный payout-адрес, выберите функцию
авторизации майнера и подпишите escrow-ключ из шага 1. Кошелек вернет сертификат из
128 шестнадцатеричных символов. Сертификат публичный; приватный ключ и seed-фраза
никуда не передаются.

### Шаг 3. Передайте сертификат майнеру

Первый запуск с сертификатом:

```text
--escrow-cert <128 hex>
```

Полный пример Windows:

```bat
InterMiner-cuda.exe -a keryxhash -s stratum+tcp://krx-solo.baikalmine.com:9021 -w keryx:ВАШ_АДРЕС.rig01 --threads 0 --cuda-no-blocking-sync --escrow-cert ВАШ_СЕРТИФИКАТ
```

InterMiner проверит сертификат до подключения и сохранит его в `escrow.cert`. При
следующих запусках `--escrow-cert` можно убрать. Вместо строки можно сразу использовать:

```text
--escrow-cert-file <путь к escrow.cert>
```

На HiveOS `escrow.key`, `escrow.cert` и состояние escrow по умолчанию хранятся в
`/hive/miners/custom/interminer-state/`, чтобы переживать обновления майнера.

## 4. Смена адреса или переустановка

Сертификат привязан к паре «payout-адрес + escrow-ключ майнера». Новый сертификат нужен,
если изменился payout-адрес или был потерян `escrow.key`. Сохраните `escrow.key` вместе
с настройками рига. Никому не отправляйте этот файл.

## 5. Типичные ошибки

### Старая версия майнера

Сообщение об unsupported miner после H6 означает, что используется версия ниже 1.2.5.
Обновите сам майнер; изменение командной строки это не исправит.

### Нет сертификата direct-solo

```text
H6 direct solo requires a delegation certificate
```

Повторите шаги из раздела 3.

### Сертификат не соответствует адресу

```text
escrow certificate does not match the payout address and escrow key
```

Сертификат выпущен для другого payout-адреса или другого `escrow.key`. Выпустите новый
сертификат для ключа, который майнер печатает при текущем запуске.

### Повреждена модель

Если после полной проверки модели появляется `failed verification`, удалите файл модели
и маркер `.ok`, затем запустите майнер снова:

```text
<каталог моделей>/Qwen3.5-9B-abliterated/model.gguf
<каталог моделей>/Qwen3.5-9B-abliterated/.ok
```

Расположение каталога моделей:

| Запуск | Каталог |
| --- | --- |
| обычный | `models/` рядом с InterMiner |
| HiveOS | `/hive/miners/custom/interminer-models/` |
| с `--model-dir DIR` | указанный `DIR` |

На HiveOS каталог вынесен из папки конкретной версии, поэтому сохраняется при обновлении.
Майнер также печатает выбранный каталог модели в начале лога.

## 6. Адреса пулов

| Режим | Адрес | Сертификат пользователя |
| --- | --- | --- |
| PPLNS | `stratum+tcp://krx.baikalmine.com:9020` | не нужен |
| Direct-solo | `stratum+tcp://krx-solo.baikalmine.com:9021` | нужен |

## 7. Полезные параметры

| Параметр | Назначение |
| --- | --- |
| `--list-gpus` | показать список видеокарт и выйти |
| `--gpu 0,2` | майнить только на выбранных картах |
| `--threads 0` | отключить CPU-майнинг |
| `--password VALUE` | пароль пула, если он требуется |
| `--escrow-cert <128 hex>` | передать сертификат строкой и сохранить его |
| `--escrow-cert-file FILE` | прочитать сертификат из файла |
| `--hiveos` | использовать постоянные каталоги HiveOS для моделей и состояния |
| `--model-dir DIR` | использовать отдельный каталог моделей |
| `--version` | показать версию майнера |
| `--help` | показать все параметры |
